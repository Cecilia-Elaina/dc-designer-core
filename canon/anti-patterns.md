# 反模式规范

## 1. 概述

反模式（Anti-patterns）是本插件禁止生成的低质量结果。识别和避免反模式是保证教学系统设计质量的关键。本规范列出了所有禁止的反模式，并说明了正确的做法。

## 2. 流程反模式

### 2.1 跳过需求评估

**反模式描述：**
直接假设所有问题都是培训问题，不进行绩效分析就确定教学目的。

**错误示例：**
```
用户："我想教学生Python循环"
插件：直接开始设计Python循环教学
```

**正确做法：**
```
用户："我想教学生Python循环"
插件："在开始设计之前，我需要先了解：
1. 学生在循环学习中遇到了什么具体问题？
2. 这些问题是培训能解决的吗？还是有其他原因（如设备不足、时间不够）？
3. 您有学生学习困难的具体数据吗？"
```

**禁止理由：** 企业培训场景中，很多绩效问题不是培训能解决的。

### 2.2 跳过教学分析

**反模式描述：**
直接从教学目的跳到绩效目标，不进行教学分析和从属技能分析。

**错误示例：**
```
教学目的：学生能编写Python for循环
直接跳到：绩效目标：给定范围，学生能写出for循环代码
```

**正确做法：**
```
教学目的：学生能编写Python for循环
教学分析：
1. 识别重复操作
2. 确定循环次数/范围
3. 翻译为可迭代对象
4. 编写循环框架
5. 填充循环体
6. 调试和测试
从属技能分析：每个步骤的子技能和入门技能
绩效目标：基于分析为每个技能编写目标
```

**禁止理由：** 不做分析会导致教学不完整、顺序混乱、入门技能假设错误。

### 2.3 跳过形成性评价

**反模式描述：**
设计完教学材料后直接投入使用，不进行形成性评价。

**错误示例：**
```
设计完成 → 直接给学生使用 → 收集期末考试成绩
```

**正确做法：**
```
设计完成 → 一对一评价 → 修改 → 小组评价 → 修改 → 场景评价 → 修改 → 投入使用
```

**禁止理由：** 不做形成性评价会导致教学材料存在未发现的缺陷。

### 2.4 反馈循环断裂

**反模式描述：**
形成性评价发现的问题没有反馈到教学分析和目标层面，只修改了材料表面。

**错误示例：**
```
形成性评价发现学生不会做某类题目
修改：在材料中增加该类题目的例题
不检查：是否需要修改教学分析和目标
```

**正确做法：**
```
形成性评价发现学生不会做某类题目
1. 检查：是否需要修改教学分析（是否遗漏了技能）
2. 检查：是否需要修改绩效目标（目标是否不合理）
3. 检查：是否需要修改评价方案（评价是否不恰当）
4. 检查：是否需要修改教学策略（策略是否无效）
5. 最后修改教学材料
```

**禁止理由：** 只修改材料表面问题，不解决根本原因。

## 3. 内容反模式

### 3.1 普通教案冒充教学系统设计

**反模式描述：**
只生成教学目标、教学过程、板书设计等普通教案内容，声称是完整的教学系统设计。

**错误示例：**
```
# 教案
教学目标：...
教学重点：...
教学难点：...
教学过程：导入→新授→练习→小结
板书设计：...
```

**正确做法：**
```
# 教学系统设计
一、教学目的（含依据）
二、教学分析（含流图）
三、学习者分析
四、绩效目标（含三成分）
五、评价方案（含对齐检查）
六、教学策略（含五成分）
七、教学材料
八、形成性评价方案
九、修改记录
```

**禁止理由：** 普通教案缺少系统化设计的关键成分。

### 3.2 课标依据缺失还装作确定

**反模式描述：**
K12场景中，教学目的没有课标依据，但插件仍然声称目标是"合适的"。

**错误示例：**
```
教学目的：学生能理解Python循环的概念
依据：（空）
插件："这个目标很合适，可以开始设计了"
```

**正确做法：**
```
教学目的：学生能理解Python循环的概念
⚠️ 注意：这个目标缺少课标依据。
K12教学目的必须有课程标准、教材或考试要求的依据。
请提供：
1. 相关课标条款
2. 教材对应章节
3. 考试大纲要求
```

**禁止理由：** 没有依据的教学目的无法保证质量和合法性。

### 3.3 评价证据与目标错位

**反模式描述：**
评价证据测量的内容与绩效目标描述的行为不一致。

**错误示例：**
```
绩效目标：给定一组数据，学生能选择合适的循环结构
评价证据：请写出for循环的语法格式
```

**正确做法：**
```
绩效目标：给定一组数据，学生能选择合适的循环结构
评价证据：给定以下三个任务，请为每个任务选择最合适的循环结构（for/while/不需要循环），并说明理由：
1. 打印1到100的所有整数
2. 从用户输入中读取数据直到输入-1
3. 计算列表中所有正数的和
```

**禁止理由：** 评价错位会导致无法准确评估教学效果。

### 3.4 模糊行为动词

**反模式描述：**
绩效目标中使用"知道"、"理解"、"了解"等不可观测的动词。

**错误示例：**
```
绩效目标：
1. 知道for循环的语法
2. 理解循环的执行过程
3. 了解break和continue的区别
```

**正确做法：**
```
绩效目标：
1. 给定for循环代码，能逐行解释执行过程
2. 给定一个任务描述，能选择并写出合适的for循环结构
3. 给定一段包含break/continue的代码，能预测输出结果
```

**禁止理由：** 模糊动词无法观测和测量。

### 3.5 形成性评价流于形式

**反模式描述：**
设计了形成性评价但只是走过场，没有真正收集数据和改进教学。

**错误示例：**
```
形成性评价：
一对一评价：找了3个学生看了看材料
小组评价：让学生做了一下练习
场景评价：在课堂上试讲了一次
```

**正确做法：**
```
形成性评价：
一对一评价：
- 选择3个典型学习者（高于平均、中等、低于平均）
- 观察他们使用材料的过程，记录遇到的困难
- 收集他们的标注、测试成绩、态度问卷
- 分析数据，确定修改内容

小组评价：
- 选择8-20个学习者，覆盖不同能力水平
- 按照实际使用方式组织学习
- 收集前测/后测成绩、态度问卷、时间记录、评论
- 使用题目-目标分析表分析数据

场景评价：
- 在真实教学环境中进行
- 设计者只观察不干预
- 收集完整数据
```

**禁止理由：** 形式化的形成性评价无法发现真正的问题。

### 3.6 忽略隐私保护

**反模式描述：**
在输出中包含学生个人身份信息。

**错误示例：**
```
学习者分析：
- 学生A（具体学号不记录）数学基础较差
- 学生B（具体学号不记录）学习态度不积极
```

**正确做法：**
```
学习者分析：
- 班级中有约30%的学生数学基础较弱
- 约20%的学生学习态度需要加强
```

**禁止理由：** 保护学生隐私是法律和伦理要求。

## 4. 架构反模式

### 4.1 来源混淆

**反模式描述：**
将AI生成内容标注为官方依据，或将不同来源的内容混合标注。

**错误示例：**
```
教学目的：学生能...（依据：课程标准）
实际上：课程标准中没有这个具体要求，是AI根据课标精神推断的
```

**正确做法：**
```
教学目的：学生能...
依据：
- 课程标准第X条：[具体条款] — 可信度：高
- AI推断：根据课标精神，这个目标是合理的 — 可信度：不确定
```

**禁止理由：** 来源混淆会误导教师和评估者。

### 4.2 一致性检查缺失

**反模式描述：**
修改了一个模块的内容，但没有检查对其他模块的影响。

**错误示例：**
```
修改：将教学目标从"编写for循环"改为"编写for和while循环"
不检查：是否需要修改教学分析、评价方案、教学策略
```

**正确做法：**
```
修改：将教学目标从"编写for循环"改为"编写for和while循环"
检查：
- 教学分析：需要补充while循环的分析
- 绩效目标：需要补充while循环的目标
- 评价方案：需要补充while循环的评价证据
- 教学策略：需要补充while循环的教学活动
- 教学材料：需要补充while循环的材料
```

**禁止理由：** 不检查一致性会导致模块间不匹配。

### 4.3 教师确认缺失

**反模式描述：**
在关键决策点没有获得教师确认就继续设计。

**错误示例：**
```
插件："我确定了教学目的，现在开始教学分析..."
（没有询问教师是否同意这个目的）
```

**正确做法：**
```
插件："根据您的描述，我初步确定了以下教学目的：
[目的陈述]
请确认这个目的是否准确反映了您的教学需求？
[确认] [修改]"
```

**禁止理由：** 教学设计是教师主导的过程，插件只是辅助工具。

## 5. 反模式检查清单

在输出任何设计内容前，应检查：

- [ ] 是否跳过了需求评估？
- [ ] 是否跳过了教学分析？
- [ ] 是否跳过了形成性评价？
- [ ] 反馈循环是否完整？
- [ ] 是否只是普通教案？
- [ ] K12场景是否有课标依据？
- [ ] 评价证据是否与目标对齐？
- [ ] 行为动词是否可观测？
- [ ] 形成性评价是否认真设计？
- [ ] 是否保护了学生隐私？
- [ ] 来源标注是否准确？
- [ ] 是否检查了一致性？
- [ ] 是否获得了教师确认？

## 6. 违规处理

### 6.1 一票否决

以下反模式必须一票否决：
- 跳过需求评估（企业培训场景）
- 课标依据缺失还装作确定
- 评价证据与目标错位
- 在输出中包含学生个人身份信息
- 来源混淆（AI推断标注为官方依据）

### 6.2 警告

以下反模式应发出警告：
- 跳过教学分析
- 跳过形成性评价
- 使用模糊行为动词
- 形成性评价流于形式
- 未检查一致性
- 未获得教师确认
