# 一致性检查规则

## 1. 概述

一致性检查是 Dick & Carey 模型的核心质量保障机制。模型的每个模块输出都是下一个模块的输入，任何不一致都会导致最终教学产品的质量下降。本规范定义了模块间的一致性检查规则。

## 1.1 评价证据的定义

本规范中"评价证据"是一个广义概念，包括但不限于：

- **客观题**：简答题、填空题、选择题、匹配题、判断题
- **主观题**：论述题、分析题、案例分析题
- **表现性任务**：口头报告、演示、角色扮演、实验操作
- **作品**：报告、设计、项目、编程作品、艺术创作
- **操作表现**：现场操作、技能演示、模拟任务
- **观察记录**：课堂观察、行为观察、小组互动观察
- **态度量表**：兴趣问卷、态度问卷、自评量表
- **评分规准**：核查表、等级量表、评分指南
- **工作现场任务**：岗位实操、现场考核、项目验收

## 2. 一致性检查矩阵

### 2.1 教学目的 ↔ 教学分析

| 检查项 | 规则 | 不一致时的处理 |
|--------|------|--------------|
| 行为覆盖 | 教学分析流图必须覆盖教学目的中的所有行为 | 补充分析步骤 |
| 学习类型 | 分析中的学习类型分类必须与目的行为匹配 | 重新分类 |
| 环境一致性 | 分析中隐含的应用环境必须与目的中的环境一致 | 调整分析 |

### 2.2 教学分析 ↔ 学习者分析

| 检查项 | 规则 | 不一致时的处理 |
|--------|------|--------------|
| 入门技能 | 学习者分析中的入门技能评估必须与分析图中虚线以下的技能对应 | 调整虚线位置 |
| 群体特征 | 学习者群体特征必须支持分析中确定的教学复杂度 | 调整教学顺序 |
| 先备知识 | 学习者的先备知识必须与分析中的从属技能要求匹配 | 调整入门技能假设 |

### 2.3 教学分析 ↔ 绩效目标

| 检查项 | 规则 | 不一致时的处理 |
|--------|------|--------------|
| 技能覆盖 | 每个从属技能必须有对应的绩效目标 | 补充目标 |
| 步骤覆盖 | 目的分析中的每个步骤必须有对应的目标 | 补充目标 |
| 学习类型 | 目标中的行为动词必须与技能的学习类型匹配 | 修改动词 |
| 层次关系 | 目标之间的层次关系必须与分析图一致 | 调整目标顺序 |

### 2.4 绩效目标 ↔ 评价方案

| 检查项 | 规则 | 不一致时的处理 |
|--------|------|--------------|
| 目标覆盖 | 每个绩效目标必须有对应的评价证据 | 补充评价证据 |
| 行为对齐 | 评价证据测量的行为必须与目标中的行为一致 | 修改评价证据 |
| 条件对齐 | 评价证据的条件必须与目标中的条件一致 | 修改评价证据 |
| 标准对齐 | 评价证据的掌握标准必须与目标中的标准一致 | 调整标准 |
| 学习类型 | 评价证据类型必须适合目标的学习类型 | 选择合适类型 |

### 2.5 评价方案 ↔ 教学策略

| 检查项 | 规则 | 不一致时的处理 |
|--------|------|--------------|
| 评测覆盖 | 教学策略中的评测活动必须覆盖所有评价证据类型 | 补充评测活动 |
| 时机对齐 | 前测、后测的时机必须与策略中的安排一致 | 调整时机 |
| 分组一致 | 评测时的学生分组必须与策略中的分组一致 | 调整分组 |

### 2.6 教学策略 ↔ 教学材料

| 检查项 | 规则 | 不一致时的处理 |
|--------|------|--------------|
| 成分覆盖 | 材料必须实现策略中的所有五个学习成分 | 补充材料 |
| 内容一致 | 材料内容必须与策略中的内容呈现一致 | 修改材料 |
| 活动一致 | 材料中的学习者活动必须与策略中的参与活动一致 | 修改活动 |
| 例子一致 | 材料中的例子必须与策略中规划的例子一致 | 补充例子 |
| 媒体一致 | 材料的媒体格式必须与策略中的媒体选择一致 | 调整格式 |

### 2.7 教学材料 ↔ 形成性评价

| 检查项 | 规则 | 不一致时的处理 |
|--------|------|--------------|
| 材料覆盖 | 形成性评价必须覆盖所有材料对应的学习目标 | 补充评价证据 |
| 难度适当 | 评价证据难度必须与材料的难度水平匹配 | 调整难度 |
| 时间合理 | 评价时间必须与材料的学习时间匹配 | 调整时间 |

### 2.8 形成性评价 ↔ 修改教学

| 检查项 | 规则 | 不一致时的处理 |
|--------|------|--------------|
| 数据驱动 | 每个修改必须有对应的评价数据支持 | 补充数据或删除修改 |
| 问题定位 | 修改必须准确定位到有问题的模块 | 重新定位 |
| 影响检查 | 修改必须检查对其他模块的影响 | 补充影响分析 |

## 3. 一致性检查算法

### 3.1 覆盖性检查

```python
def check_coverage(source_module: str, target_module: str) -> dict:
    """
    检查目标模块是否覆盖了源模块的所有内容
    
    Returns:
        {
            "covered": list — 已覆盖的项目,
            "missing": list — 缺失的项目,
            "coverage_rate": float — 覆盖率
        }
    """
```

### 3.2 对齐性检查

```python
def check_alignment(source_item: dict, target_item: dict) -> dict:
    """
    检查两个项目之间的对齐程度
    
    Returns:
        {
            "aligned": bool,
            "misaligned_fields": list — 未对齐的字段,
            "alignment_score": float — 对齐分数
        }
    """
```

### 3.3 一致性检查主函数

```python
def check_alignment_all(project: dict) -> dict:
    """
    执行所有模块间的一致性检查
    
    Returns:
        {
            "overall_consistent": bool,
            "checks": [
                {
                    "pair": "module_a ↔ module_b",
                    "consistent": bool,
                    "issues": list — 不一致问题
                }
            ],
            "recommendations": list — 修改建议
        }
    """
```

## 4. 一致性检查报告格式

```markdown
# 一致性检查报告

## 检查概要
- 检查时间：[时间]
- 检查范围：[模块范围]
- 总体一致性：[通过/未通过]

## 详细检查结果

### 1. 教学目的 ↔ 教学分析
- 状态：[通过/未通过]
- 问题：[问题列表]
- 建议：[修改建议]

### 2. 教学分析 ↔ 学习者分析
...

### N. 形成性评价 ↔ 修改教学
...

## 总结
- 一致性问题总数：[数量]
- 严重问题：[数量]
- 一般问题：[数量]
- 建议修改优先级：[排序]
```

## 5. 一致性修复流程

```
发现不一致 → 评估严重程度 → 确定修复策略 → 执行修复
    ↓
严重问题 → 必须立即修复 → 重新检查
一般问题 → 可以稍后修复 → 记录并跟踪
```

## 6. 自动化检查工具

`alignment_checker` MCP Tool 提供以下检查功能：

1. **check_goal_analysis_alignment** — 检查教学目的与教学分析的一致性
2. **check_analysis_learner_alignment** — 检查教学分析与学习者分析的一致性
3. **check_analysis_objective_alignment** — 检查教学分析与绩效目标的一致性
4. **check_objective_assessment_alignment** — 检查绩效目标与评价方案的一致性
5. **check_assessment_strategy_alignment** — 检查评价方案与教学策略的一致性
6. **check_strategy_material_alignment** — 检查教学策略与教学材料的一致性
7. **check_full_alignment** — 执行所有一致性检查
