# DC Designer 通用启动提示词

请在当前工作区接入并启动 DC Designer v2，并用它协助我完成中国大陆 K12 信息科技 / 信息技术教学系统设计。

项目仓库：<https://github.com/xiajiadi/dc-designer-core>

请按下面顺序执行：

1. 先判断当前智能体宿主的能力。如果当前工作区还没有这个项目，请以项目级方式从上面的仓库地址读取或获取它；不要把项目复制到用户全局插件目录。
2. 读取仓库中的 `README.md`、`docs/agent-compatibility.md`、`docs/v1_plugin_contract.md` 和对应的 `skills/` 文件。
3. 如果宿主支持从远程来源安装，使用上面的仓库地址；如果只能从本地目录加载，先在当前工作区获取仓库并加载。优先按项目级方式接入：Codex 使用 `.codex-plugin`，Claude Code 使用 `.claude-plugin`，Gemini CLI 使用 `gemini-extension.json`。只有确实需要用户确认的全局安装，才先向我说明并等待确认。
4. 如果宿主支持 MCP，接入仓库中的 `dc-designer-mcp`，入口为 `python mcp-server/server.py`。如果宿主没有 MCP，就使用仓库内的本地脚本和 Skill 文件完成同一流程。
5. 接入成功后立即开始设计；如果接入没有完成，明确报告阻断原因和下一步，不要假装已经安装。
6. 默认先做“课标约束快速设计”。如果我要求完整协同设计、评审或修订，切换到相应 Skill；不要强行把三种流程合并。
7. 第一次只询问完成当前阶段最必要的 1 至 3 项信息。不得编造教材版本、学生比例、成绩、学校条件或课堂效果。
8. 所有关键判断都要区分官方依据、教师输入、教材 / 学校资料、学习者数据、AI 推断和 AI 建议。没有教师确认时只能称为候选或草案。
9. 设计完成后按项目合同生成或说明报告、教师手册、学生学习单、矩阵、JSON / Markdown 和可编辑图等交付物；没有真实形成性评价数据时保持“待实施 / 待验证”，不得生成虚构效果。

现在先完成接入检查，然后告诉我：使用了哪一种接入方式、三个 Skill 是否可用、MCP 是否可用，以及开始设计还缺哪些信息。
