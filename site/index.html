01 / WHY A SYSTEM

教学设计不是一段生成文字。
它是一组必须互相证明的决定。

从一个问题开始→

从评价需求和绩效差距出发，确定可观察的教学目的；再把目的拆成技能、从属技能和入门技能，决定如何教、如何评、需要什么材料。

插件负责把复杂的系统化设计过程组织起来，教师始终保留对课标依据、学习者情境和关键结论的确认权。

02 / TWO WAYS IN

从你熟悉的地方开始。

同一套 Dick–Carey 方法，适应两种真实的设计现场。

01

STANDARD FAST / 课标约束快速设计

把常规课题快速变成一份能用的系统设计。

输入学段、课题、教材位置、课时、设备和匿名班级共性学情。插件检索课程标准候选，搭建目标、教学分析、评价、策略和材料，再把需要教师确认的决定清楚列出来。

适合一线教师
日常备课↗
02

COLLABORATIVE / 完整协同设计

把模糊的教学想法，逐步变成可审查的方案。

从需求和绩效差距开始，一阶段一阶段地提问、给出候选、说明理由、等待确认。每次修改都保留决策记录，并重新检查目标、评价、策略、材料和来源的一致性。

适合课程研发
协同设计↗

03 / THE MODEL

让每一步，都有下一步的理由。

不是套模板，而是让系统设计的逻辑显形。

01评价需求与教学目的

明确要解决的绩效问题，以及学习者最终需要完成的真实表现。

02教学分析与技能图

拆解主要步骤、从属技能和入门技能，区分目的流程与程序控制流。

03学习者与环境

描述匿名的班级共性学情、学习环境和真实应用环境，不凭空填写个人数据。

04绩效目标与评价证据

用条件、行为和标准写出可观察目标，并让编程任务包含运行、测试和调试证据。

05教学策略与材料

把目标和评价转化为教学活动、教师话术、学习单、量规与课堂材料。

06形成性评价与修订

真实数据尚未产生时明确标记待实施；获得反馈后先做影响分析，再重新对齐。

目的证据课堂

04 / SOURCE WITH CONTEXT

课标不是一句标签。
它应该回到证据。

内置知识库保存课程方案和课程标准的来源元数据、公开链接与条款候选。教师自己的教材、教案和校本资料单独保存在本机，并明确区分来源等级。

01官方来源

文件、发布机构、日期、版本和适用范围。

02条款候选

链接、章节和定位清楚可查，候选不冒充已确认依据。

03教师资料

作为情境参考，保留 C1 私有来源边界。

04教师确认

关键依据和设计决定由教师审核后进入最终门禁。

条款候选不等于教师已确认

06 / LOCAL FIRST

教师的资料，
留在教师的设备里。

01

教师上传的教材、教案、试卷和校本资料保存在本机知识库。

02

只接收匿名聚合的班级共性学情，不保存学生姓名、学号、电话或个人成绩。

03

没有真实形成性评价数据时，报告明确写“待实施 / 待验证”，不编造效果。

08 / QUESTIONS

开始之前，先知道这些。

它适合哪些教师？+

当前面向中国大陆小学、初中和普通高中信息科技 / 信息技术教师。高校、职教、企业培训和其他学科不在 v1 产品范围内。

它会替教师直接决定教学目标吗？+

它会检索依据、提出候选并说明理由，但教学目的、入门技能、学情和策略等关键结论需要教师确认或修改，未确认时不会标记为最终版。

安装是不是完全自动的？+

官网按钮会复制 Codex 的 GitHub marketplace 导入指令。实际安装仍受当前账户、工作区权限和管理员设置影响。

没有形成性评价数据也能使用吗？+

可以生成形成性评价方案和待收集字段，但不会把推断写成真实效果；报告会保留“待实施 / 待验证”状态。
